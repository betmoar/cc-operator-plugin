## 3. Unverified / open — what this build did NOT establish

- **Live-session hook behavior inside a real CC session** — block/release in an
  actual `Stop` event, and `SubagentStop` non-interference (a dispatched
  subagent's completion must not trip the main Stop hook). Recorded as
  **DEFERRED-VERDICT** in the ledger. *Verify by:* running spec Phase 2's four
  demonstration transcripts inside a live operated session. This build proved it
  only at fixture level (hook fed JSON on stdin).
- **`${CLAUDE_PLUGIN_ROOT}` expansion at hook runtime** — confirmed by
  convention (7 sibling plugins, cc-repete verbatim) and by static validation,
  **not** by observing the variable expand in a live Stop event. *Verify by:*
  triggering the hook in a session with the plugin installed and checking it
  resolves the script path.
- **Opus-as-operator actually obeying the charter** (spec U1) and **CLAUDE.md
  pointer vs. inline re-injection persistence** (spec U3) — both are Phase 1
  pilot measurements, out of this build's scope by design.
- **`--inline` command path** — authored but exercised only by reading; not run
  through a live `/operator:start --inline`.

## 5. Stop conditions — when NOT to continue

- **Do not self-administer the pilots.** Phases 1/3 measure operator behavior; a
  session that built the thing cannot grade itself (plan risk #4). Separate
  sessions by design.
- **Do not mutate user-global settings to make the hook fire.** If a live
  session shows `hooks/hooks.json` isn't honored, STOP and report options —
  global-settings mutation is out of contract (plan risk #1).
- **Do not negotiate the 150-line charter cap** to fit more content (plan risk
  #3). The cut list is spec D2; trusted-judgment items go first.
- **Do not compensate in charter prose for known product-skill defects** (trace
  omission, stochastic activation, S13/S14 cluster) — that is treadmill round 3
  (spec D1 anti-scope).
